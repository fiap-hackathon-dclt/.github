# 0006 — Go 1.27 e Python 3.13, com as dependências atualizadas junto

**Status:** aceita · **Domínio:** Serviços · Observabilidade · **Validação:** não validada · **Data:** 25/11/2026 · **Fase:** 5

## Contexto

O código do curso chegou em Go 1.21 e Python 3.9, ambos fora de suporte.

No ToggleMaster, a [0007](https://github.com/fiap-tech-challenge-devops/.github/blob/main/docs/decisoes/0007-permanecer-em-go-1-25.md) fixou Go 1.25 com OTel 1.46, para não subir de versão sem razão. A razão agora existe: o **Go 1.25 saiu de suporte em 19/08/2026**, e a linha atual do OTel Go (`v1.47.0`) exige Go 1.26.

No Python, o OTel exige 3.10 ou mais. E o `psycopg2-binary==2.9.5` do `ngo-service` não tem pacote pronto para Alpine com Python 3.13: segundo o PyPI, esse pacote só existe a partir da `2.9.10`. Sem ele, a imagem precisaria de compilador e `libpq-dev`.

As dependências também estão defasadas: `aws-sdk-go` v1, fora de suporte desde 2025; `pgx` v4; Flask 2.2.2, gunicorn 20.1.0 e boto3 1.26.

## Decisão

| Linguagem | Versão | Suporte |
|---|---|---|
| Go | **1.27** | até o lançamento do 1.29 |
| Python | **3.13** | até 10/2029 |

As dependências sobem na mesma mudança:

- `donation-service`: `aws-sdk-go` v1 para v2 e `pgx` v4 para v5
- `ngo-service` e `volunteer-service`: Flask, gunicorn, `psycopg2-binary` e boto3 nas versões atuais

O que o Trivy ainda acusar depois disso é tratado caso a caso.

## Alternativas descartadas

**Go 1.26.** Também roda o OTel atual, mas sai de suporte uma versão antes da 1.27, sem nada que compense.

**Python 3.14.** Suportado até 2030, mas não testado com OTel sobre Alpine. A 3.13 foi validada no ToggleMaster.

**Python 3.15.** Lançado em 10/2026, novo demais para confiar que as bibliotecas de instrumentação já o suportem.

**Subir a linguagem e deixar as dependências para depois.** O `psycopg2-binary` antigo impediria a imagem Alpine sem compilador, e o `aws-sdk-go` v1 ficaria fora de suporte de qualquer jeito.

## Consequências

- O `go-ci` e o `python-ci` têm Go 1.21 e Python 3.9 como padrão. Os chamadores passam as versões novas explicitamente
- A troca do `aws-sdk-go` para a v2 muda o código de publicação no SQS do `donation-service`; a do `pgx` muda a abertura da conexão
- A instrumentação usa a linha atual do OTel, sem a trava de versão que o ToggleMaster precisou

## O que esta decisão não resolve

- As versões exatas de cada dependência, que ficam nos `go.mod` e `requirements.txt`
- A troca para Go 1.28 ou Python mais novo durante o projeto, que será deliberada, como na 0007 do ToggleMaster
